#### Q2.1 What are the shapes of train_x and train_y, and where did the number 784 come from?
Shapes are images of 28x28. To feed it into the fully-connected network, it must be flattened into a 1D vector of 28x28=784 which is the total number of pixels in each image.

#### Q2.2 Is the training set balanced? What does that tell you about which metric to use, and what is chance-level accuracy?
The training set is perfectly balanced (10 classes, 6000 instances per class, 10% each). This means plain accuracy is a fair metric — no need for class weighting, F1, or balanced accuracy. Chance-level accuracy is 10% (1/10), since random guessing among 10 equally likely classes gives 10%.

#### Q4.1 Why is the scaler fitted only on train_x? Describe concretely what goes wrong otherwise.
To avoid data leaking. If we for example used the validation data to fit the scaler aswell, it would influence the mean we use to normalize the data. Thus the validation data wouldn't be an independent metric to test our model. 


#### Q4.2 What does stratify=official_train_y do, and why does it matter for a dataset that is already perfectly balanced?
Stratify is here to guarantee that both the training and validation set have equal class representation. So as to not have a biased model or validation set.

With stratify=y, each split is guaranteed to have (as close as integer division allows) exactly 10% per class :
- Remove variance from the validation set : no unlucky split with unequal class representation.
- Results are more repoducible across experiments.
- This is even more important with imbalanced data.


#### Q4.3 Random splitting is fine here. Under what circumstances would it be wrong?
Random state makes the split reproducible across multiple runs. Without it every split would be different each time. Every run gives the same train/val partition.
